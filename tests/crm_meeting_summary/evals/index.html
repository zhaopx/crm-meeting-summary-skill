上半层

互动 agent + 挂载 skill

调度层

互动 agent 是唯一入口。它不自己吞掉全部业务逻辑，而是把不同任务分发给对应 skill。当前重点是总结 skill，后面待办 skill 和其他 skill 继续按同一挂载方式扩展。

唯一入口

互动 agent

统一接任务、理解上下文、决定本轮调哪个 skill，不把系统画成多个平级入口。

作用：任务编排、上下文承接、技能路由。 边界：互动 agent 是入口，不替代 skill 本身的专门逻辑。

并列能力

总结 skill

当前最核心的业务 skill，把会议输入变成销售可消费的总结输出。

主链：输入理解 → 模板加载 → knowhow 加载 → memory 加载 → 生成总结。 特点：更重业务判断与表达质量，直接决定总结成品长什么样。 落地页：进入总结对比页
并列能力

待办 skill

把会议里真正要推进的动作拆成 owner、前置条件、依赖和阻塞，不和总结 skill 混成一个东西。

主链：任务抽取 → 优先级判断 → owner 归属 → 待办输出。 特点：更重动作闭环，而不是生成一篇可读总结。 依赖：也会消费 memory，不是独立于 memory 的旁路能力。
扩展能力

其他 skill

后续新增能力继续挂在这里，比如评审、诊断、复盘，不再每加一个能力就多画一层结构。

原则：新增的是能力，不是新顶层。 运行方式：按任务只加载所需子 skill、上下文和 memory。

memory 体系

共享底座

所有 skill 最终都往下依赖同一套 memory。这里不是一个空盒子，而是继续分成对象 memory、用户 memory、agent memory 三块，分别承接不同维度的长期信息。

统一承接

memory

作为共享记忆底座，承接对象事实、用户偏好、agent 可复用经验。上层 skill 不再每次从零开始推理，而是从 memory 中拿到稳定支撑。

服务对象：总结 skill、待办 skill、其他 skill。 设计方案：查看 memory 整体设计与技术方案
↓
memory 内部组成

这三块不是平级产品模块，而是 memory 体系内部的分区，各自解决不同类型的信息沉淀。

内部三分区
对象维度

对象 memory

沉淀 account、opportunity、stakeholder、commitment 这类业务对象的长期状态、模式和关键判断。

典型内容：阶段、风险、阻塞、承诺链、关系判断。 价值：让总结 skill 读到“这单现在怎么回事”，而不是只看单次会议。
用户维度

用户 memory

沉淀用户偏好、工作方式、长期约束和稳定指令，避免每个 session 重新校准一次。

典型内容：输出偏好、闭环要求、语言风格、任务轻重偏好。 价值：让互动 agent 和各类 skill 更贴着真实协作方式执行。
系统维度

agent memory

沉淀 agent 自己可复用的经验、路径、规则和上下游协作记忆，支撑后续自动化与稳定执行。

典型内容：可复用经验、已验证路径、技能协作经验、系统侧知识。 价值：让 agent 不只是会做，还会越做越稳定。

结构要点

这页现在在讲什么

先有互动 agent 它是统一入口，负责把任务路由到总结 skill、待办 skill 或其他 skill。
再有挂载 skill skill 是被调度的能力，不是新的顶层系统入口。
最后统一落到 memory 所有 skill 共享同一底座，再由对象 memory、用户 memory、agent memory 分别承接不同信息。
