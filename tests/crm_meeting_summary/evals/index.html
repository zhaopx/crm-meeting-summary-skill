架构图

真正的结构是 2 层主结构，数据源属于 memory 内部

这张图只表达两件事。第一，互动 agent 是顶层总入口。第二，memory 体系是下面的共享底座，而且那些特征数据源、CRM 原始事实、人工沉淀、其他数据源都属于 memory 的输入来源，不和 memory 平级。

第一层

互动 agent

唯一总入口

系统顶层只有一个互动 agent。它先接住任务，再决定当前轮次调用哪些 skill。总结 skill、待办 skill、其他 skill 都是这一层下面挂载的能力，不是新的顶层入口。

入口节点

互动 agent

统一接住一次互动，理解本轮目标，再向下编排能力。它负责组织和调度，不直接等于某一个具体产出。

职责：决定这轮要调用哪些 skill。 边界：不把全部业务逻辑塞进一个大 skill。
↓
挂载能力

总结 skill

把会议内容压缩成销售、售前、管理者能直接读的总结输出。

产出：会议快照、关键判断、下一步动作、风险与待确认问题。
挂载能力

待办 skill

把会议里真正要推进的动作拆成可执行项，而不是继续写一份概括总结。

产出：owner、动作、前置条件、阻塞项、后续依赖。
挂载能力

其他 skill

后续接入的新能力继续挂在这里，不单独升成新的顶层结构。

意义：把“现在有几个 skill”和“系统有几层”明确分开。
第二层

memory 体系

共享依赖层

上面所有 skill 都统一依赖这一层。它不是总结 skill 私有附属，也不是临时笔记区。更关键的是，下面这些特征数据源、CRM 原始事实、人工沉淀和其他数据源，都属于 memory 的输入来源，是 memory 内部承接的来源，不是和 memory 平级的新一层。

共享底座

memory 体系

把稳定信息沉淀下来，供总结 skill、待办 skill 和其他 skill 统一消费。系统不会退化成每次只看当前输入的一次性生成器。

服务对象：第一层全部 skill。 承接内容：对象级长期记忆、上下文补充、跨会话稳定信息。
↓
