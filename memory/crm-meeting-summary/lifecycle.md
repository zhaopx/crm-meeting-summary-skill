# Memory Lifecycle

## 目标

这个文件只回答一个问题：

**CRM fact 在什么条件下进入 memory，进入后什么时候留在 `today`，什么时候升级到 `long_term`。**

结构定义和字段字典不在这里展开，统一看 `schema.md`。

## 两层的语义边界

### `today`
`today` 表示当前这次 interaction 之后，这个对象在今天的状态、信号和变化。

特点：
- 更新频率高
- 允许快速变化
- 服务当前状态判断
- 不要求长期稳定

适合放入 `today` 的内容：
- 今天的关注点
- 今天的新风险信号
- 今天的推进状态
- 今天的态度变化
- 今天的新 blocker 或新机会

不适合放入 `today` 的内容：
- 原始会议纪要全文
- 没有对象归属的散乱事实
- 已经稳定且跨会议成立的长期特征

### `long_term`
`long_term` 表示跨多次互动后稳定下来的对象特性、模式和结构性背景。

特点：
- 更新频率低
- 稳定性更高
- 服务长期解释与模式判断
- 不能被单次噪音轻易改写

适合放入 `long_term` 的内容：
- 长期决策风格
- 长期偏好
- 长期敏感点
- 重复出现的 blocker 模式
- 稳定审批路径
- 长期关系基线

不适合放入 `long_term` 的内容：
- 单次会议即时状态
- 一次性 next action
- 仅由今天会议得出的未确认结论

## 状态

### `active`
当前 profile 仍有效，并且最近有 evidence 支撑。

### `stale`
没有被明确反证，但已经较久未被确认。

### `contradicted`
被当前 evidence 明确反证，不能继续作为正向依据。

### `archived`
明确归档，不再参与默认读取。

## 状态迁移建议

```text
today
  -> 刷新覆盖            新 meeting 到来
  -> 清空                当天语义失效

long_term
  -> active              持续被新 evidence 支撑
  -> stale               长期未确认
  -> contradicted        被当前 evidence 明确反证
  -> archived            明确归档
```

## CRM fact 到 memory 的升级规则

### 1. 先记事实，再判断是否进入 memory
CRM 里的订单、销售记录、阶段变化、任务完成，本质上先是业务事实。

默认顺序：
1. 先进入 CRM facts
2. 判断这次事实是否改变了对象今天的状态
3. 只有形成稳定模式时，才升级到 `long_term`

### 2. 哪些事实只留在 CRM
适用条件：
- 一次性操作
- 没有解释价值
- 不能说明对象今天状态
- 不能支持长期模式判断

例子：
- 新建订单
- 新增销售记录
- 补录一次联系日志
- 创建一次普通任务

### 3. 哪些事实可以写入 `today`
适用条件：
- 这次事实改变了对象当前状态
- 能表达今天的风险、推进、态度、角色变化
- 主要服务当前 meeting 后的判断

例子：
- 商机今天从评估进入采购沟通
- 客户今天明确表示先解决稳定性再谈续费
- 联系人今天从旁听者变成推动者
- 内部 owner 今天承诺本周五前补材料

### 4. 哪些事实可以升级到 `long_term`
必须同时满足：
- 不是单次噪音
- 跨多次互动重复出现
- 已经能解释对象的稳定特性或模式
- 有连续 evidence 支撑

例子：
- 客户连续多次都要求先看归因，再讨论扩量
- 联系人连续多次都先要书面材料，再安排会
- 商机多次都卡在财务测算
- 内部销售连续多个周期都能按时兑现承诺

### 5. 推荐升级路径

```text
CRM fact
  -> 不改变对象状态                只保留在 CRM
  -> 改变对象今天状态              写入 today
  -> 多次重复并稳定成立            升级为 long_term
```

### 6. 升级 `long_term` 的最低判断原则
- 单次出现，不升级
- 两次出现，只能候选，不直接写死
- 多次重复且无明显反例，才进入 `long_term`
- 一旦被当前 evidence 反证，降级为 `stale` 或 `contradicted`

## 使用红线

- `today` 不等于会议纪要全文
- `today` 不应直接复制 raw notes
- `long_term` 不能写入单次即时状态
- `stale` 的 long_term 特征不能单独抬高关键判断置信度
- `contradicted` 的 long_term 特征只能用于冲突说明
