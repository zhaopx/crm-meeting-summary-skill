# Best-case 目录

best-cases 是短参考，用来展示一份强 CRM meeting summary 长什么样，以及为什么强。
它们不是模板，而是 judgment anchors。

## 目的

- 提供 evidence-to-judgment 推理的具体例子
- 展示好的风险处理与下一步纪律
- 避免复制措辞，同时提升判断质量

## best-case 应包含什么

每个 best-case 应包含：
1. scenario label and slug
2. industry label（如适用）
3. 简短 meeting context（2-4 行）
4. 使用到的 evidence excerpts（短、精确引用）
5. 从 evidence 派生出的 key judgments
6. 呈现出的 risk signals 以及原因
7. recommended next actions，以及它们为何由证据导出
8. 明确写出的 missing information

## best-case 应避免什么

- 长 transcript 或完整 raw notes
- 容易诱导 copy-paste 的重格式化
- invented CRM 或 memory facts
- 无 listed evidence 支撑的结论

## 命名规则

使用短文件名：
- `needs-clarification__general-b2b__v1.md`
- `commercial-negotiation__saas__v1.md`

## 评审规则

每个 best-case 都必须能用 `crm-meeting-summary-review` 的同一套 rubric 审查。
如果一个 best-case 过不了 review，就不能作为 reference 使用。
